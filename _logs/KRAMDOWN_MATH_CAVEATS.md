# kramdown 数学公式渲染注意事项

本文记录了这次调试 `_blogs/2026-07-29-group-theory.md` 时发现的问题：一些在 **Markdown Preview Enhanced（本地预览）** 和**标准 LaTeX/MathJax/KaTeX** 里都能正常渲染的写法, 在本站实际使用的 **kramdown**（Jekyll 的 Markdown 处理器）流水线里会被破坏. 写新的数学向博客时请参照下面的替换表. 

## 根本原因

1. **kramdown 只原生识别 `$$...$$`, 完全不认识单个 `$...$`. **
   - `$$...$$` 会被 kramdown 当作一个"数学元素"整体保留, 原样转成 `\(...\)`（同一行内）或 `\[...\]`（独占一行）, 里面的反斜杠、花括号等字符**不会**被后续处理动过. 
   - 单个 `$...$` kramdown 完全不认识, 会被当成**普通段落文本**, 走一般的转义/HTML 处理逻辑——这是本文所有 bug 的根源. 
   - 站点的 MathJax 是通过 `_includes/footer/custom.html` 里追加的 `inlineMath: [['$','$'], ...]` 配置才认识单个 `$...$` 的；kramdown 本身对此一无所知. 

2. **kramdown 对普通段落文本有一份转义字符表**（`ESCAPED_CHARS`）：
   ```
   \ . * _ + ` < > ( ) [ ] { } # ! : | " ' $ = -
   ```
   任何 `\` + 表中字符, 反斜杠都会被**吃掉**, 只剩下裸字符. 大部分字符（`(` `)` `[` `]` `.`）本来就不需要反斜杠就能当 `\left`/`\right` 分隔符, 所以不受影响；但 **`{` `}`** 必须写成 `\{` `\}` 才能当分隔符使用, 被吃掉反斜杠后就成了非法语法. 

3. **kramdown 的表格解析器极度敏感**：只要一行里出现**未转义的 `|`**（哪怕只有一个, 哪怕没有 `---` 分隔行）, 就会把这一整行拆成表格单元格. 这是独立于上面两点的另一个 bug, 且发生在"是否识别为数学"之前的分块阶段, 所以就算包在 `$$...$$` 里也救不了. 

4. **本站通过 GitHub Pages 安全模式部署**（`Gemfile` 里的 `github-pages` gem）, 线上构建会**忽略 `_plugins/` 里的自定义插件**. 这意味着无法通过写一个 kramdown 插件来"从根上"修掉表格解析器或转义规则——插件只在本地 `jekyll serve`/Docker 预览生效, 线上会不一致. 因此这次全部采用**内容层面的替换**, 不依赖任何插件. 

## 替换表

在**单个 `$...$`（行内数学）** 里, 以下写法即使在 Markdown Preview Enhanced / 标准 LaTeX 里正常, 在本站也**不能用**, 必须换成右边的写法：

| 不能用（本地/标准 LaTeX 正常, 本站会炸）                         | 原因                                                                                                                         | 应该换成                                      |
| ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| `\left\|`（配合 `\right\|`）绝对值/范数分隔符                    | 裸 `\|` 触发表格解析器, 整段被拆成 `<table>`                                                                                 | `\left\vert` / `\right\vert` / `\middle\vert` |
| 单独的裸 `\|`（"整除"、集合的"使得", 如 `n\|rk`、`\{x\|p(x)\}`） | 同上                                                                                                                         | `\mid`                                        |
| `\left<` / `\right>`（尖括号, 如群的生成元记号 `<r,s\|...>`）    | `<` `>` 根本不是 MathJax/KaTeX/标准 LaTeX 认可的 `\left`/`\right` 分隔符, 会报 "Missing or unrecognized delimiter for \left" | `\left\langle` / `\right\rangle`              |
| `\{` / `\}`（花括号, 如集合记号 `\{e\}`、`\left\{ \right\}`）    | kramdown 的转义表会把 `\{`/`\}` 的反斜杠吃掉, 变成非法的裸 `{`/`}`                                                           | `\lbrace` / `\rbrace`                         |

**安全、不需要改的**：`\left(` `\right)`、`\left[` `\right]`、`\left.` `\right.` 本来就不需要反斜杠转义, 不受影响；所有写在**独占一行的 `$$...$$`** 块里的内容（矩阵、`\begin{array}` 等）kramdown 会原样保留, 也不受影响. 

## 使用建议（新写数学时）

- **只有在单个 `$...$` 行内数学里才需要按上表替换**；独立成行的 `$$...$$` 块不受影响, 可以照常使用 `\{ \}`、`\|` 等标准写法. 
- 如果不确定, 统一使用右边这套"纯字母"命令（`\vert` `\mid` `\langle` `\rangle` `\lbrace` `\rbrace`）总是安全的, 两边（本地预览、线上）渲染结果一致. 
- 替换后如果命令名后面紧跟字母（例如 `\midrk`、`\lbracee`）, LaTeX 会把它们当成一个未定义命令, 记得在命令和后面的字母之间留一个空格（`\mid rk`、`\lbrace e`）.
